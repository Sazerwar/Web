# Розподілена клієнт-серверна система ресурсоємних обчислень СЛАР (Метод Якобі)

**Технологічний стек:**
- **Бекенд (Application Servers):** **C# / ASP.NET Core 8** (`backend/HeavyTasksCluster.csproj`) — багатопотокові обчислення СЛАР $A \cdot x = b$ методом Якобі (`Task.Run` + `CancellationTokenSource`), JWT-автентифікація, Server-Sent Events (SSE), інтеграція з PostgreSQL (Entity Framework Core / Npgsql) та Redis (`StackExchange.Redis`).
- **Фронтенд (Client UI):** **React 18 + Vite** (`frontend/`) — чистий мінімалістичний веб-інтерфейс із ручним табличним редактором матриці $A$ та вектора $b$, відображенням прогресу в реальному часі, історією задач та окремою сторінкою адміністрування кластера.
- **Балансувальник навантаження та HTTPS:** **Nginx Reverse Proxy** (`nginx/nginx.conf`) — термінація SSL/TLS (HTTPS порт `443`, HTTP $\to$ HTTPS `301` редірект) та розподіл трафіку алгоритмом `least_conn` між серверами застосувань.
- **Спільне сховище стану та черга:** **PostgreSQL 16** (користувачі, історія та результати задач) + **Redis 7** (FIFO-черга задач `tasks:queue`, Pub/Sub синхронізація прогресу й скасування між вузлами, heartbeat-моніторинг серверів).

## Реалізація всіх 8 пунктів вимог

1. **Обмеження максимальної складності задачі (`Пункт 1`):**
   - Розмірність системи $N \in [2..3000]$, кількість ітерацій $\le 50\,000$, максимальний час виконання $\le 60\text{ с}$.
   - Подвійна перевірка: на клієнті у React (`App.jsx`) та на сервері в C# (`TasksController.ValidateComplexity`). При перевищенні ліміту часу `CancellationTokenSource.CancelAfter` автоматично перериває задачу зі статусом `FAILED`.
2. **Інформування про хід виконання (`Пункт 2`):**
   - C# воркер (`JacobiWorkerService.cs`) на кожному кроці обчислення публікує поточний відсоток (`0% -> 100%`), номер ітерації та похибку через Redis Pub/Sub у потік SSE (`/api/tasks/events`).
3. **Перегляд стану, скасування та історія задач (`Пункт 3`):**
   - До 20 задач на користувача зберігаються в PostgreSQL (`tasks`).
   - Активні або очікуючі задачі можна зупинити кнопкою **«Скасувати»** (міжсерверна зупинка через канал Redis `tasks:cancel`). Завершені задачі можна повторити або видалити у вікні **«Історія задач»**.
4. **Автентифікація клієнтів та захищений протокол HTTPS (`Пункт 4`):**
   - Авторизація за допомогою JWT (`AuthController.cs`) та хешування паролів `BCrypt`.
   - Весь зовнішній трафік проходить через HTTPS (`https://localhost`, порт `443`).
5. **Балансування навантаження (`Пункт 5`):**
   - Nginx розподіляє запити між C# серверами застосувань (`node-app-1`, `node-app-2` тощо). Кожен сервер повертає свій ідентифікатор у заголовку `X-Server-Id` і записує його в поле `server_id` кожної задачі.
6. **Черга ресурсоємних задач із розрахунком часу очікування (`Пункт 6, +бали`):**
   - Кожен сервер виконує максимум 2 важкі задачі одночасно (`MaxConcurrentTasksPerServer = 2`). Надлишкові задачі потрапляють у чергу Redis (`QUEUED`) з відображенням позиції `#1, #2...` та зворотним відліком орієнтовного часу очікування.
7. **Горизонтальне масштабування серверів (`Пункт 7, +бали`):**
   - Сервіс `AutoScalerService.cs` автоматично масштабує кількість активних вузлів кластера від `2` до `5` при накопиченні черги або дозволяє керувати кількістю серверів вручну з панелі адміністратора.
8. **Адмін-панель (`Пункт 8, +бали`):**
   - Окрема сторінка **«Адміністрування»** (`AdminView.jsx`, доступна для облікового запису `admin` / `admin123`), де в реальному часі виводяться:
     1) стан усіх серверів кластера (CPU %, RAM, активні воркери, статус `ONLINE`, uptime);
     2) поточна черга задач у Redis;
     3) таблиця всіх задач усіх користувачів із кнопкою **«Примусово зупинити»**.

## Запуск проєкту

```powershell
docker compose up --build -d
```

Після запуску відкрийте у браузері:
- **Адреса сайту:** `https://localhost`
- **Логін адміністратора за замовчуванням:** `admin`
- **Пароль адміністратора:** `admin123`
